# LetsTalk Constitution

Non-negotiable rules that every spec, plan and task list is checked against. Derived from `CLAUDE.md` and the existing architecture.

## Principles

### 1. Security first
- Credentials and tokens must not be readable by browser JavaScript.
- No secrets (keys, API tokens, connection strings) in commits. `appsettings.json` values stay empty or come from user secrets and environment variables.
- Swagger and other developer tooling stay limited to the Development environment.
- CORS uses explicit origins from configuration, never "allow any" together with credentials.

### 2. Generated code is regenerated, not edited
- API clients are generated by NSwag from the API's OpenAPI spec (`nswag/*.nswag`). Change the API, then regenerate the affected client.
- Only regenerate the clients a feature needs. `frontend-next/` is out of bounds unless a spec says otherwise.

### 3. Back end: event-driven microservices with provider-neutral persistence
- Services stay separate (API, Authentication, FileStorage, Notifications, ...). Cross-service calls go through the existing gRPC and broker clients.
- Application code depends on `*AgnosticService` abstractions only. A persistence feature is implemented for every provider (EntityFramework/MySQL, MongoDB, CosmosDB) with identical behavior.
- Shared registration lives in `Infrastructure/DependencyInjection`.

### 4. Test-first, with the project's tools
- Back end: NUnit + Moq + FluentAssertions. Test names follow `Method_WhenCondition_ShouldOutcome`; repeated literals are class-level `private const`. Persistence service tests mock repositories and `IMapper` (see `.github/instructions/persistence-service-tests.instructions.md`).
- Angular: vitest. Next.js has no tests and is not touched by default.
- Tests for a behavior are written before the code that implements it, and every functional requirement has at least one test or a manual quickstart step.

### 5. Front-end conventions
- Angular (`frontend/`): NgRx state, `ChangeDetectionStrategy.OnPush`, services in `services/`, generated code in `api-client/` and `protos/`.
- Lint and format rules (`npm run lint`, stylelint, prettier) must pass.
- `frontend-next/` follows its own `AGENTS.md` and is a work in progress that stays untouched unless stated.

### 6. Backward compatibility during a migration
- A change that alters the auth or API contract keeps existing clients working until they are migrated, or the spec states the breaking change and its migration path.

### 7. Small, reviewable, spec-driven changes
- Work follows `spec.md` (what and why) -> `plan.md` (how) -> `tasks.md` (do). The spec stays technology-free.
- Behavior changes update the spec first, then the plan and tasks.
- Unresolved `[NEEDS CLARIFICATION]` markers block planning.

## Governance
- The constitution is amended by editing this file in its own commit, with the reason in the message.
- A plan that violates a principle must list the violation and its justification in its "Constitution check" section.
